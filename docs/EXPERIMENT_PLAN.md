# План эксперимента и критерии качества

## Постановка

Задача: сопоставить текст клиентского обращения с одной из банковских категорий. В первый запуск берём 8 типов обращений; чтобы опробовать все 77, нужно использовать `--all-labels`.

## Правила подготовки данных

1. Только официальная обучающая часть BANKING77 участвует в формировании train и validation.
2. Отдельная официальная test-часть используется для окончательной оценки. **Ни одна модель не подбирается по test.**
3. Ограничение `--train-per-class 70` применяется отдельно к каждому классу с фиксированным seed=42.
4. Train/validation разбиваются стратифицированно (80% / 20%).
5. Метки переводятся из исходных индексов BANKING77 в компактные номера восьми выбранных категорий.

## Сравнение

Сначала TF-IDF + Logistic Regression: простой и интерпретируемый baseline. Затем небольшой BERT c собственным train loop PyTorch: предобученный encoder + классификационная голова. BERT-эпоха выбирается по validation macro-F1. После выбора обе модели оцениваются на **одинаковом** test.

| Метрика | Зачем нужна |
|---|---|
| Macro-F1 | Главная: усредняет F1 по всем типам обращений без весов классов |
| Accuracy | Показывает долю верных классификаций в целом |
| Per-class precision/recall/F1 | Находит слабые категории, которые агрегаты скрывают |
| Ошибочные пары категорий | Позволяет объяснить ограничения модели |

Порог `review_required` на softmax-score выбран эвристически и не калиброван. В прикладной системе его потребуется подбирать по стоимости ошибочной автоматической маршрутизации и доле ручных проверок.

## Контроль после обучения

- [ ] Команда train завершилась без исключения и создала сохранённую модель.
- [ ] `metrics.json` содержит размеры train/val/test и метрики обеих моделей.
- [ ] В тестовую часть не попало ни одного элемента из train/validation.
- [ ] Выбрана эпоха по val, а не по test.
- [ ] `bert_errors.csv` и `baseline_errors.csv` прочитаны, выписаны 3 типичных ошибки.
- [ ] `predict` возвращает метку и score для тестового текста.
- [ ] Для резюме используются только действительно измеренные значения и выполненные действия.

## Почему не Spark / Hadoop / Hive

Вакансия указывает эти технологии как дополнительное преимущество. Здесь мы сознательно сфокусировались на ядре роли: PyTorch, train loop, Transformers, классический ML, выбор метрик, банковский текст. Раздельный Spark/Hadoop кейс уже есть в других учебных проектах; смешивать всё в один репозиторий не требуется.
